# Design

## Context

声音由后台 ffplay（`-nodisp`）播放源文件，与画面的 ffmpeg 分开，按段启动（video-player design D5、D10）。ffplay 没有窗口，运行中收不到音量按键；`-volume 0–100` 只在启动时生效。`$.audio.play` 只能放 mod 自带文件，不能用来放视频音轨。

## Goals / Non-Goals

**Goals:**
- 调音量不动画面、不开新段
- 音量设定跨会话保留，读到坏数据时退回默认

**Non-Goals:**
- 超过 100% 的放大、渐变、按文件记音量
- 不断声的实时调节（需要能接收控制的音频通道，目前沙箱没有）

## Decisions

### D1 调音量 = 只重启 ffplay
段里的 ffplay 单独记一个结束函数（`stopSound`），不混在段的 `stops` 里。调整时结束旧 ffplay，按「段起点 + 段开始后经过的真实时间」作为 `-ss`，带新的 `-volume` 重新启动。用真实时间而不是屏幕上的帧号，是因为声音本来就按真实时间走，解码落后时帧号会偏小。备选：SIGSTOP/重启整段——会让画面闪回解码中，放弃。

### D2 静音 = 不起 ffplay
有效音量为 0（静音或设为 0）时不启动 ffplay，省一个进程；取消静音时按 D1 从当前位置启动。

### D3 音量放在模块变量 + `$.store`
`{ level, isMuted }` 存在模块变量里供每段启动 ffplay 时读，变化时写 `$.store` 的 `volume` 键；`session.start`（含热重载）时读回并校验（level 为 0–100 整数、isMuted 为布尔），不合法退回 `{ 100, false }`。不进 `$.state`：面板只通过状态行文字看到它，状态行本来就由 state 驱动。

### D4 纯函数放 `hooks/volume.ts`
校验、加减（钳在 0–100、取消静音）、切换静音、有效音量、状态行标签都是纯函数，`register.tsx` 只做接线。

### D5 按钮
控制行在跳转按钮之后加 `🔉`（j）、`🔊`（k）、`🔇`/`🔈`（m），hjkl 习惯里 h/l 已是跳转，j/k 上下正好对应音量；m 为 mute。视频没有声音时整组不显示。

## Risks / Trade-offs

- 每次调整声音断 0.1–0.3 秒，连续按会断续 → 可接受；与暂停继续时的接续方式一致
- 重启后的 ffplay 起播延迟可能让声音略晚于画面 → 与段开始时的误差同量级，不额外处理
